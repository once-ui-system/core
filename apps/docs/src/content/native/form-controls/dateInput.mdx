`DateInput` takes the same main props as on the web (`label`, `value`, `defaultValue`, `onChange`, `minDate`, `maxDate`, `locale`). It looks like an [`Input`](/native/form-controls/input) showing the date, and a tap opens a [`DatePicker`](/native/form-controls/datePicker) in a bottom sheet; picking a day closes it. See the [web DateInput](/form-controls/dateInput) for the same component in the browser.

Inside a [`Form`](/native/form-controls/form) it takes the form's size and a stacked group's corners, and a `Field` can wrap it like any input.

## Differences from the web

- The value can't be typed: the field opens the calendar instead of a keyboard.
- No time picker yet.
- `id` is accepted and ignored.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | | The field's label and the sheet's title. |
| `value` | `Date` | | The date, when you own it. |
| `defaultValue` | `Date` | | The first date when the field owns it. |
| `onChange` / `onValueChange` | `(date: Date) => void` | | Called with the picked day. |
| `minDate`, `maxDate` | `Date` | | The days that can be picked. |
| `locale` | `string` | `"en-US"` | The field's date format and the calendar's names. |
| `open`, `defaultOpen`, `onOpenChange` | | | The sheet's state, when you own it. |

Every other prop is `Input`'s (`size`, `error`, `errorMessage`, `description`, `disabled`…).
