`@once-ui-system/native` brings Once UI's basic components to iOS and Android apps built with React Native. They take the same props as the web components and read the same design tokens, so a screen written with Once UI looks and reads the same on a phone.

It is a preview. Most apps should keep shipping Once UI on phones as the web build wrapped in a native shell (the Stack mobile target); use this package when the app itself has to be native.

**Props follow core 3.0.** The components take the 3.0 props of `@once-ui-system/core`, not the 2.x ones: state is `checked` / `defaultChecked` / `onCheckedChange`, `value` / `defaultValue` / `onValueChange` and `open` / `defaultOpen` / `onOpenChange`; accessible names are `aria-label`; colour is `tone` and look is `variant`; Text and Heading take `textVariant`; Badge and Chip are `Tag`; and a number on a spacing or size prop is points (the web reads it on the token scale, which is the same at the default root size). The renames are listed under "Coming from the 2.x props" below.

## Install

Needs React 19, React Native 0.79 or later (Expo SDK 53 and up) and `react-native-svg` 15, which Expo includes. Preview versions are published to the `next` tag. The [quick start](/native/quick-start) covers Expo and bare React Native apps, safe areas and fonts.

codes={[
  {
    code: "npm install @once-ui-system/native@next",
    language: "bash",
    label: "npm"
  }
]} />

## Usage

Wrap the app in `ThemeProvider`. It takes the same style options as on the web, with the same defaults; `theme="system"` follows the device.

<CodeBlock marginTop="8" marginBottom="24"
codes={[
  {
    code:
`import { Button, Column, Heading, Text, ThemeProvider } from "@once-ui-system/native";

export default function App() {
  return (
    <ThemeProvider brand="orange" neutral="sand" solid="color">
      <Column padding="20" gap="12" background="page" fill>
        <Heading>Morning Coffee</Heading>
        <Text onBackground="neutral-weak">Three more coffees and the next one is on us.</Text>
        <Button label="Add stamp" onPress={() => {}} />
      </Column>
    </ThemeProvider>
  );
}`,
    language: "tsx",
    label: "App.tsx"
  }
]} />

## Responsive props and safe areas

`Flex`, `Row`, `Column` and `Card` take the same breakpoint props as on the web (`xl`, `l`, `m`, `s`, `xs`), and `safeArea` pads a view clear of the notch and home indicator once the app passes the screen's insets to `ThemeProvider`. See [responsive layouts](/native/basics/responsive) and the [quick start](/native/quick-start).

## Differences from the web

- **Units.** A number on a spacing or size prop is density-independent points. On the web 3.0 reads it on the token scale (16 = 1rem, following `data-scaling`), which is the same number of px at the default root size; here it does not follow the screen's rem or `scaling`. Tokens work as on the web, and so do `"24px"` and `"1.5rem"` strings; rem follows the screen size, 15pt on phones and 16pt on tablets.
- **Touch.** Pressed states replace hover, and small controls take taps from at least 44pt around them without being drawn larger.
- **Clipping.** `radius` does not clip children. Pass `overflow="hidden"` when it should; on iOS that also hides the view's shadow.
- **Dialog** opens as a bottom sheet unless `variant="center"`; the web's default is the centred card.
- **Tag** `variant="gradient"` is a flat brand tint, and `effect` draws no shine.
- **Media** shows images only. Enlarging on tap, videos and YouTube embeds are not supported.
- **Tabs** have no arrow-key navigation, so `activation` has no effect.
- **Core 3.0 names.** `Accordion` also takes `defaultOpen` and `onOpenChange`, `Tabs` takes `onValueChange`, and `StatusIndicator` takes `scheme`, so code written for 3.0 works here too.
- **Safe areas.** The app passes the screen's safe areas to `ThemeProvider`, as shown below, instead of the browser providing them (see the [quick start](/native/quick-start)).

## Coming from the 2.x props

The first preview took the 2.x props. Rename them as core's 3.0 codemod does on the web:

| 2.x | 3.0 |
| --- | --- |
| `onToggle` on Checkbox, RadioButton and Switch | `onCheckedChange` |
| `onChange` on RadioGroup and SegmentedControl, `onSelect` on Select | `onValueChange` |
| `aria-label` | `aria-label` |
| Button and IconButton `variant="danger"`, `"success"`, `"warning"` | `tone="danger"`, and so on |
| `variant="quaternary"` | `variant="ghost"` |
| Tag `scheme`; Feedback, Toast and `addToast` `variant` | `tone` |
| Text and Heading `variant` | `textVariant` |
| `Badge` | `Tag variant="announce"`, with `label` for `title` and `prefixIcon` for `icon` |
| `Chip` | `Tag selected`; `selected` now defaults to false |
| Dialog `hideClose` | `showClose={false}` |
| Avatar `statusIndicator={{ color }}` | `statusIndicator={{ scheme }}` |
| A number on spacing or sizes: rem | px; write `"20rem"` to keep the old size |

## Design tokens

Both packages read one token export generated from the web package's SCSS tokens, so a token change reaches the web and native apps together. The same file ships as `@once-ui-system/core/tokens.json` for other tools, such as Figma or Swift and Kotlin code generators.
