## Starter template

Create a new Once UI app with our starter repository. It will install dependencies and set up the recommended structure:

<CodeBlock marginBottom="32" marginTop="8"
codes={[
  {
    code: "npx create-once-ui-app@latest my-app",
    language: "bash",
    label: "CLI"
  },
  {
    code: "git clone https://github.com/once-ui-system/nextjs-starter.git",
    language: "bash",
    label: "Manual"
  }
]} />

Or add Once UI to an existing project:

<CodeBlock compact marginBottom="32" marginTop="8"
 codes={[
  {
    code: "npm install @once-ui-system/core",
    language: "bash"
  }
]} />

Upgrading an app from 1.8? Follow the [migration guide](https://github.com/once-ui-system/core/blob/main/MIGRATING.md): a codemod does most of it, and it lists what is left in the order that keeps your app building.

## Dependencies

Installed with Once UI Core, nothing to do:

| Package | Version | Purpose |
| --- | --- | --- |
| `@floating-ui/react-dom` | `^2.1.9` | Positioning for dropdowns, tooltips and popovers |
| `clsx` | `^2.1.1` | Conditional class names |
| `date-fns` | `^4.4.0` | Date pickers and inputs |

Your app provides these. Components ship their styles as precompiled CSS modules, which Next.js, Vite and other bundlers handle with no setup, so your app needs no `sass` (3.0 dropped it as a peer):

| Package | Version | Purpose |
| --- | --- | --- |
| `react` | `>=19` | React |
| `react-dom` | `>=19` | React DOM |

## Optional dependencies

Install these only for the features that need them. Each module named here comes from its own subpath, not the package root:

| Package | Version | Used for |
| --- | --- | --- |
| `next` | `>=15.5` | Next.js apps: `LayoutProvider` from `@once-ui-system/core/next` routes links and images through `next/link` and `next/image` |
| `recharts` | `^3.10.1` | Charts and gauges from `@once-ui-system/core/data` |
| `prismjs` | `^1.30.0` | `CodeBlock` from `@once-ui-system/core/code` |
| `compressorjs` | `^1.3.0` | `MediaUpload` from `@once-ui-system/core/media` |

Icons ship inlined, so no icon library is required. To use more icons, register any React icon components — react-icons, lucide or your own SVGs — through [`IconProvider`](/contexts/iconProvider).
