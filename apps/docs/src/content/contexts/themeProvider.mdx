The `ThemeProvider` is a context that persists user theme preferences and syncs with the system’s light/dark setting. It provides a `useTheme` hook to manage theme state at runtime and sets data attributes on the `<html>` element.

## Simple setup

Wrap your app with `ThemeProvider` and pass the style configuration as props.

## Advanced setup

Keep every style choice in one file, typed with [defineConfig](/config#defineconfig), and spread it into the provider. The keys are the provider's prop names, so nothing is cast or renamed. We also recommend a `Providers` component to wrap your app.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  lineNumbers
  codes={[
    {
      code:
`"use client";

import { DataThemeProvider, IconProvider, ThemeProvider, ToastProvider } from "@once-ui-system/core";
import { dataStyle, style } from "@/resources/once-ui.config";

export function Providers({ children }: {
    children: React.ReactNode
}) {
    return (
      <ThemeProvider {...style}>
        <DataThemeProvider {...dataStyle}>
          <ToastProvider>
            <IconProvider>
              {children}
            </IconProvider>
          </ToastProvider>
        </DataThemeProvider>
      </ThemeProvider>
    );
}`,

      label: "Providers.tsx"
    },
    {

  style: {

A 2.0 `Providers` that casts each value (`brand={style.brand as Schemes}`) still compiles; `defineConfig` is what makes the casts unnecessary.

If you don't pass any props to the `ThemeProvider`, it will fall back to defaults. If the visitor has theme preferences (saved in localStorage), the `ThemeProvider` will use those. To force a theme, set `theme` on the `ThemeProvider` as `light` or `dark`.

## Custom color

The quickest way to a custom palette is one colour. Give `brandSeed`, `accentSeed` or `neutralSeed` a hex, `rgb()` or `oklch()` value and the whole 12-step scheme is [generated from it](/basics/color#custom-schemes). A seed implies `"custom"` when you have not named the scheme yourself.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  isCollapsible={false}
  lineNumbers
  codes={[
    {
      code:
`export const { style } = defineConfig({
  style: {
    brandSeed: "#5A93FC",
    accentSeed: "oklch(0.72 0.17 40)",
    neutral: "gray",
  },
});

// layout.tsx: the scheme is generated on the server
<ThemeInit config={style} />

// Providers.tsx
<ThemeProvider {...style}>`,
      language: "tsx",
      label: "once-ui.config.js"
    }
  ]}
/>

`ThemeInit` generates the scheme on the server and renders it into a `<style>` next to its script, so the page paints with the custom brand colour from the first frame. `ThemeProvider` applies the same values on the client, which is what lets a seed change at runtime, for example in an editor previewing a colour. A seed that cannot be parsed is ignored, and the scheme keeps its default rather than pointing at nothing.

To hand-pick every step instead, set the scheme to `custom` and supply the `--scheme-*` variables yourself. You can generate palettes using the [Once UI customize page](https://once-ui.com/customize).

## SSR hydration

Add the `<ThemeInit>` component to the `<head>` to set the initial theme before hydration in `layout.tsx`. It will prevent flash of unstyled content (FOUC). It takes the same `style` object as the provider, plus `dataStyle` for the chart mode:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  lineNumbers
  codes={[
    {
      language: "tsx",
      label: "layout.tsx",
      code: `<head>
    <ThemeInit config={style} dataStyle={dataStyle} />
</head>
`,
    },
  ]}
/>

Each key is written to `<html>` as `data-<kebab-key>` (`solidStyle` becomes `data-solid-style`), and `dataStyle.mode` as `data-viz-style`. A choice the visitor saved, through a `StylePanel` for example, is applied on top before the first paint.

The 2.0 form, with attribute names as keys (`"solid-style": style.solidStyle`), is still accepted. Its `"viz-style"` key is the chart *mode*: the 2.0 docs filled it from `dataStyle.variant`, which matches no style, so charts fell back to categorical. Passing `dataStyle` reads `dataStyle.mode` instead.

## Style overrides

The `ThemeProvider` relies on data attributes to set theme and style preferences. Data modes are inherited from the parent and can be applied to any
semantic HTML element, providing simple, seamless style overrides.

Just add the `data-theme`, `data-neutral`, `data-brand`, `data-accent`, `data-border`, `data-surface`, `data-solid`, `data-solid-style`, `data-transition` or `data-scaling` attributes to any semantic HTML element to override its default style.

On `Flex`, `Row`, `Column` and `Grid`, the four you reach for most are typed props, checked against the same values as this provider: `theme` writes `data-theme`, `themeBorder` writes `data-border`, `themeSolid` writes `data-solid` and `themeSurface` writes `data-surface`. `border` and `solid` already mean colours on those components, hence the prefix.

```tsx
<Column theme="dark" themeSolid="contrast" background="page" padding="40">
  ...
</Column>
```

## Root font size and cursor

`desktopSize`, `tabletSize` and `mobileSize` set the root font size, in px, for each width range, which is what every `rem` in the system resolves to. `cursorInteractive` sets the cursor over buttons, links and other interactive elements. They have no defaults of their own: left unset, nothing is written to `<html>` and the stylesheet's values apply (16px, 16px, 15px and `pointer`).

```tsx
<ThemeProvider desktopSize="17" mobileSize="14" cursorInteractive="default">
```

They belong in the `style` section of the config like any other key, so `ThemeInit` applies them before the first paint.

## Persistence

Style choices are mirrored into `localStorage` under `data-<kebab-key>`. Set
`persistence` to change that:

- `"local"` — the default described above.
- `"none"` — choices apply to the document but are not stored. Use this when
  a host owns the state, such as an editor holding an unsaved draft.
- an adapter — route persistence somewhere else, such as a database.

```tsx
<ThemeProvider
  brand={site.brand}
  persistence={{
    set: (key, value) => saveSiteStyle(site.id, key, value),
  }}
>
```

`get` runs during hydration, so it must be synchronous — an await there would
show a flash of the wrong theme. When the values live somewhere async, omit
`get` and seed the provider through its props from the server instead. `set`
and `remove` may return a promise; nothing waits on them.
