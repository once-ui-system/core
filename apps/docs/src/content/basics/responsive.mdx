# Responsive Breakpoints

Once UI provides a type-safe responsive breakpoint system where each component only exposes the props it actually supports at each breakpoint.

## Breakpoint values

The breakpoints are fixed, and each one applies at its width and below. `xl` is the base state above all of them, not a media query. `LayoutProvider` reports the current one through `useLayout`; it no longer takes a `breakpoints` prop (removed in 2.0, see the [migration guide](https://github.com/once-ui-system/core/blob/main/MIGRATING.md)).

Breakpoints cascade downward: `xl` → `l` → `m` → `s` → `xs`. A value set at `xl` applies to all smaller breakpoints unless overridden.

## Per-component props

Each component defines its own breakpoint type using `BreakpointProps<Source, Keys>`, a generic that picks specific keys from the component's prop interfaces and makes them optional.

## How it works

### Type system

The generic `BreakpointProps<Source, Keys>` type picks specific keys from a source interface and makes them optional:

```ts
type BreakpointProps<Source, Keys extends keyof Source> = {
  [K in Keys]?: Source[K];
};
```

Each component defines its allowed props:

```ts
// Flex supports everything
type FlexBreakpointProps = BreakpointProps<AllFlexProps,
  | 'direction' | 'horizontal' | 'vertical' | 'center' | 'wrap' | 'flex'
  | 'padding' | 'gap' | 'width' | 'height' | 'background' | 'opacity'
  // ... etc
>;

// Grid excludes layout props
type GridBreakpointProps = BreakpointProps<AllGridProps,
  | 'columns' | 'rows'
  | 'padding' | 'gap' | 'width' | 'height' | 'background' | 'opacity'
  // ... etc (no direction, horizontal, vertical, center, wrap, flex)
>;
```

### Runtime behavior

1. **Values with a class (server-rendered):** a breakpoint value that maps to a utility class — a spacing token, a direction, an alignment — renders as that class on the server (e.g. `m-padding-l`, `s-flex-column`), so the layout is right in the first paint.

2. **Values without a class (client-rendered):** `width`, `height` and their min/max siblings, `aspectRatio`, `style`, and spacing given as a number (px) or a CSS length have no class behind them. An element that sets one of these at a breakpoint renders through `ClientFlex`/`ClientGrid`, which applies it as an inline style after hydration, for the breakpoint `LayoutProvider` reports. Prefer tokens where you can.

3. **Cascade order:** `xl` → `l` → `m` → `s` → `xs`. Larger breakpoints flow down to smaller ones. Setting `xl={{ padding: "32" }}` applies `padding: 32` at all sizes unless a smaller breakpoint overrides it.

## Custom breakpoints

Breakpoints are not configurable since 2.0: the utility classes carry the widths inside their `@media` queries, and a prebuilt stylesheet cannot follow a width an app picks at runtime. If you need a different width for one layout, write a media query in a CSS module for it.

## TypeScript API

Exported types for extending the breakpoint system:

```ts
import {
  BreakpointProps,
  FlexBreakpointProps,
  GridBreakpointProps,
  TextBreakpointProps,
  ButtonBreakpointProps,
  InputBreakpointProps,
} from "@once-ui-system/core";

// Create custom breakpoint type for your component
type MyComponentBreakpointProps = BreakpointProps<
  MyComponentProps,
  'padding' | 'background' | 'opacity'
>;
```
