`ArrowNavigation` wraps a set of items and moves focus between them with the
arrow keys. It is the component form of
[`useArrowNavigation`](/once-ui/hooks/useArrowNavigation): the hook when you own
the container and its key handler, this when you would rather not write either.

Arrow keys are the expected way to move within a *composite* widget — a menu, a
listbox, a toolbar, an emoji grid — where Tab should reach the widget once and
then hand over. [`Select`](/once-ui/form-controls/select),
[`DropdownWrapper`](/once-ui/components/dropdownWrapper),
[`DatePicker`](/once-ui/form-controls/datePicker) and
[`Kbar`](/once-ui/modules/kbar) are built on it.

## Layouts

`layout` decides which keys move focus:

- `"row"` — Left and Right.
- `"column"` — Up and Down.
- `"grid"` — all four, with `columns` giving the row width so Up and Down step
  a whole row at a time.

`wrap` (on by default) carries focus from the last item back to the first.
Turn it off for a list where hitting the end should feel like an end.

  marginTop="16"
  marginBottom="24"
  codes={[

      code:
`<ArrowNavigation layout="grid" columns={8} itemCount={emojis.length} onSelect={pick}>
  <Grid columns={8}>
    {emojis.map((emoji) => <IconButton key={emoji} ... />)}
  </Grid>
</ArrowNavigation>`,

## Which children are navigable

Items are found with
`[role="option"], [data-value], button, [tabindex]:not([tabindex="-1"])`.
Override `itemSelector` when your items are none of those, and keep
`itemCount` in step with what the selector actually matches — the count drives
wrapping and the bounds, so a mismatch shows up as arrow keys that stop one
item early.

## Trapping focus too

Set `trapFocus` to wrap the region in a
[`FocusTrap`](/once-ui/components/focusTrap). The two divide the keyboard
cleanly: the trap owns Tab and Escape, `ArrowNavigation` owns the arrows.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<ArrowNavigation
  layout="column"
  itemCount={items.length}
  trapFocus
  focusTrapActive={open}
  onEscape={close}
  onSelect={select}
>
  {children}
</ArrowNavigation>`,
      language: "tsx",
      label: "With focus trapping"
    }
  ]}
/>

## Reading the state

`useArrowNavigationContext()` returns the navigation state from inside the
subtree, for an item that needs to know it is the focused one — to paint a
highlight, or to scroll itself into view.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`function Item({ index, children }) {
  const { focusedIndex, setFocusedIndex } = useArrowNavigationContext();
  return (
    <Option
      value={String(index)}
      highlighted={focusedIndex === index}
      onMouseEnter={() => setFocusedIndex(index)}
    >
      {children}
    </Option>
  );
}`,
      language: "tsx",
      label: "useArrowNavigationContext"
    }
  ]}
/>

Syncing `setFocusedIndex` from hover is worth doing: it keeps the keyboard
highlight and the pointer from disagreeing about which item is current.
