`FormErrorSummary` lists a form's errors at the top after a failed submit. Each entry links to its field, and activating it moves focus into the control. When the summary appears, or its errors change, it takes focus itself, so a keyboard or screen reader user is brought to it rather than left on the submit button wondering why nothing happened. With no errors it renders nothing, so it can stay in the form.

## Errors

`errors` takes either a map from control id to message, which is the shape most validation libraries return, or a list of `{ id, message }`. Empty messages are skipped. An entry without an `id`, such as a server error that belongs to no field, is listed as plain text.

```tsx
<FormErrorSummary errors={[{ message: "The server could not be reached. Try again." }]} />
```

The ids are the controls' ids, the same ones a `Field` uses, so the link lands on the right element.

## Focus

`autoFocus` is on by default. Turn it off when the summary is on screen from the first render, like the preview above, because taking focus on page load moves a screen reader away from the top of the page.
