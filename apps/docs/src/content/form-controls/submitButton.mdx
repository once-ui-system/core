`SubmitButton` is a `Button` with `type="submit"` that follows its form. When a `Form`'s `onSubmit` returns a promise, the form is pending until it settles: the button shows a spinner, can swap its label for `pendingLabel`, and ignores further presses, so a double click sends one request. The form is marked `aria-busy` meanwhile.

## Pending from outside

When the submit does not run through `onSubmit`, such as a server action or a mutation hook, pass `pending` to the `Form`, or to the button itself.

```tsx
const { mutate, isPending } = useSaveProfile();

<Form as="form" pending={isPending} onSubmit={(event) => { event.preventDefault(); mutate(); }}>
  <SubmitButton>Save</SubmitButton>
</Form>
```

`useFormPending()` returns the same state for anything else in the form that should react to it.

## Why aria-disabled

While pending the button is `aria-disabled`, not `disabled`. A natively disabled button drops focus to the page the moment it is pressed with the keyboard, and the user loses their place in the form. This one keeps focus and refuses the second press. Enter in a text field is refused the same way.
