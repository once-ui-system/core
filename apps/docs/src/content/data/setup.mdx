Once UI's charts are drawn as SVG by Once UI itself: no chart library to install, no canvas, nothing to configure before the first one. They render on the server, so the first HTML already holds the chart, they size themselves to their container, and they follow the theme in light and dark.

## What's in the module

Everything imports from `@once-ui-system/core/data`.

- [`LineChart`](/data/lineChart): change over time, one or more series, stacked or not.
- [`BarChart`](/data/barChart): comparing categories, grouped, stacked or horizontal.
- [`LineBarChart`](/data/lineBarChart): a line and bars on one scale, such as a target and its actuals.
- [`PieChart`](/data/pieChart): parts of a whole, as a pie or a donut.
- [`Sparkline`](/data/sparkline): a trend in a tile or a table cell.
- [`RadialGauge`](/data/radialGauge), [`LinearGauge`](/data/linearGauge): one value against a range.
- [Building blocks](/data/parts): the header, states and screen-reader table, for your own visuals.

Not sure which? [Choosing a chart](/data/choosing) starts from the question your reader asks.

## Your first chart

<CodeBlock
  marginTop="16"
  marginBottom="24"
  previewPadding="none"
  preview={
    <LineChart
      border="transparent"
      title="Visits"
      height="20rem"
      xKey="month"
      series={[
        { key: "visits", label: "Visits" },
        { key: "signups", label: "Signups" }
      ]}
      data={[
        { month: "Jan", visits: 3200, signups: 410 },
        { month: "Feb", visits: 3550, signups: 460 },
        { month: "Mar", visits: 3400, signups: 520 },
        { month: "Apr", visits: 4100, signups: 610 },
        { month: "May", visits: 4600, signups: 700 },
        { month: "Jun", visits: 5200, signups: 790 }
      ]}
    />
  }
  codes={[
    {
      code:
`import { LineChart } from "@once-ui-system/core/data";

export function Visits() {
  return (
    <LineChart
      title="Visits"
      xKey="month"
      series={[
        { key: "visits", label: "Visits" },
        { key: "signups", label: "Signups" },
      ]}
      data={[
        { month: "Jan", visits: 3200, signups: 410 },
        { month: "Feb", visits: 3550, signups: 460 },
        { month: "Mar", visits: 3400, signups: 520 },
        { month: "Apr", visits: 4100, signups: 610 },
        { month: "May", visits: 4600, signups: 700 },
        { month: "Jun", visits: 5200, signups: 790 },
      ]}
    />
  );
}`,
      language: "tsx",
      label: "Visits.tsx"
    }
  ]}
/>

That is the whole contract: `data` is the rows, one per point on the x axis; `series` names the keys to draw; `xKey` names the one on the x axis. Swap `LineChart` for `BarChart` or `LineBarChart` and the same props draw the same data another way. [Data and series](/data/data) covers the details: dates, gaps, ordering, typed rows and reshaping API data.

The chart gives you, without asking: a tooltip on hover, keyboard navigation through the points, a legend whose entries hide and show their series, an entry animation that respects reduced motion, and a summary and data table for screen readers. See [States and interaction](/data/interaction).

## Server components

The charts are client components, so you can render them from a server component and pass them the rows you fetched there. They draw on the server, so nothing waits for JavaScript. Two things can't cross from the server to the client: function props (`valueFormat={(v) => …}`, `date.onRangeChange`) and values that are not plain data. Use the string and `Intl` forms of `valueFormat`, or wrap the chart in a client component. Details in [Numbers and dates](/data/formatting#from-a-server-component).

## Config

App-wide chart settings live in the `dataStyle` section of `once-ui.config`, next to `style`:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`const { style, dataStyle } = defineConfig({
  style: { /* … */ },
  dataStyle: {
    variant: "gradient", // flat | gradient | outline
    mode: "categorical", // categorical | divergent | sequential
    height: "24rem", // the default chart height
    axis: {
      stroke: "var(--neutral-alpha-weak)",
    },
    tick: {
      fill: "var(--neutral-on-background-weak)",
      fontSize: 11,
      line: false,
    },
  },
});`,
      language: "ts",
      label: "once-ui.config.js"
    },
    {
      code:
`<ThemeInit config={style} dataStyle={dataStyle} />

<ThemeProvider {...style}>
  <DataThemeProvider {...dataStyle}>{children}</DataThemeProvider>
</ThemeProvider>`,
      language: "tsx",
      label: "Providers"
    }
  ]}
/>

Every key is optional; what you leave out keeps its default. `ThemeInit` puts the mode on `<html>` before the first paint, so a divergent app doesn't flash categorical colours. Without `DataThemeProvider`, charts use the defaults above.

To change the settings at runtime, such as a mode switch in a settings page, use `useDataTheme()`; see [Recipes](/data/recipes#theme-switch-for-charts).

## Props every chart shares

`LineChart`, `BarChart`, `LineBarChart` and `PieChart` take these, and each page lists the props that are its own. Charts also take every [Flex prop](/components/flex) for the card: margin, `background`, `border`, `radius` and the rest.

Charts are generic over the row type, inferred from `data`: your own `interface` works as it is, and a `series` key or `xKey` that is not a key of the row is a type error.
