`Grid` is the two-dimensional counterpart to [Flex](/components/flex). Reach for
it when children should line up in both directions — a card gallery, a pricing
table, a stat row — rather than flow along one.

Everything that is not flex-specific works exactly as it does on `Flex`: the
same spacing, size, surface, display and text props, and the same breakpoint
objects. Only the two below and `masonry` are its own.

## Columns

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Grid fillWidth columns="3" m={{ columns: 2 }} s={{ columns: 1 }} gap="12">
      {["1", "2", "3", "4", "5", "6"].map((n) => (
        <Flex key={n} height="64" radius="m" background="neutral-alpha-weak" border="neutral-alpha-medium" center>
          <Text textVariant="label-default-s" onBackground="neutral-weak">{n}</Text>
        </Flex>
      ))}
    </Grid>
  }
  codes={[
    {
      code:
`<Grid fillWidth columns="3" m={{ columns: 2 }} s={{ columns: 1 }} gap="12">
    ...
</Grid>`,
      language: "tsx",
      label: "Columns"
    }
  ]}
/>

Three across, two on a tablet, one on a phone. The breakpoint objects cascade
down, so `m` also covers `s` and `xs` unless one of them says otherwise.

A responsive `Grid` is a server component, the same as a responsive `Flex`:
every breakpoint value that has a utility class — a column count, a spacing
token, `hide`, `position`, `overflow`, `opacity`, `zIndex` — is written as one,
so the layout is right in the first paint and no `LayoutProvider` is needed.
Only a value a class cannot hold (a `width`, a number of rems for spacing,
`aspectRatio` or `style`) moves the grid to the client, exactly where `Flex`
moves too.

## Auto-fit

When the column count should follow the space rather than the breakpoint, give
a minimum width instead: `minColumnWidth` fits as many columns as there is room
for, each at least that wide, and the grid reflows on its own as the container
changes — inside a sidebar, a dialog or a full page alike.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Grid fillWidth minColumnWidth="10rem" gap="12">
      {["1", "2", "3", "4", "5"].map((n) => (
        <Flex key={n} height="64" radius="m" background="neutral-alpha-weak" border="neutral-alpha-medium" center>
          <Text textVariant="label-default-s" onBackground="neutral-weak">{n}</Text>
        </Flex>
      ))}
    </Grid>
  }
  codes={[
    {
      code:
`<Grid fillWidth minColumnWidth="10rem" gap="12">
    ...
</Grid>`,
      language: "tsx",
      label: "Auto-fit"
    }
  ]}
/>

It takes what `minWidth` takes: a number is on the token scale (`256` is 16rem), a string is a spacing token or
a CSS length (`"16rem"`). The grid stays a server component — the value is a
`.columns-auto-fit` class plus a `--grid-min-column-width` custom property on
the same element, not a `style` object. A narrow container never overflows: a
single column shrinks below the minimum rather than spilling out.

`minColumnWidth` wins over `columns`, and a breakpoint `columns` still wins over
it at that width, so `minColumnWidth={16} s={{ columns: 1 }}` is auto-fit
everywhere except on a phone.

## Masonry

With `masonry`, Grid packs children into columns, each item keeping its own height, for images or cards of uneven length (2.x's `MasonryGrid`). `columns` and `gap` work as above, and `l`, `m`, `s` and `xs` change the column count per breakpoint. Flex's spacing, size and surface props still apply; the grid-only ones (`rows`, `minColumnWidth`, `xl`) do not.

<CodeBlock
    marginTop="16"
    marginBottom="24"
    previewPadding="0"
    preview={
        <Grid masonry
            padding="l"
            radius="l"
            background="neutral-medium"
            columns={6}
            m={{ columns: 4 }}
            s={{ columns: 2 }}
        >
            {[16, 6, 4, 6, 16, 12, 7, 24, 4, 12, 6, 2, 24, 17, 12, 5, 9, 6, 20, 11].map((height, index) => (
                <Flex
                    key={index}
                    background="overlay"
                    radius="l"
                    border="neutral-alpha-medium"
                    fill
                    center
                    height={height * 16}
                >{index}
                </Flex>
            ))}
        </Grid>
    }
    codes={[
        {
            code:
                `<Grid masonry
    padding="l"
    radius="l"
    background="neutral-medium"
    columns={6}
    m={{ columns: 4 }}
    s={{ columns: 2 }}
>
    {[16, 6, 4, 6, 16, 12, 7, 24, 4, 12, 6, 2, 24, 17, 12, 5, 9, 6, 20, 11].map((height, index) => (
        <Flex
            key={index}
            background="overlay"
            radius="l"
            border="neutral-alpha-medium"
            fill
            center
            height={height * 16}
        >{index}
        </Flex>
    ))}
</Grid>`,
            language: "tsx",
            label: "Masonry"
        }
    ]}
/>

### Columns

## Everything else

`Grid` takes the same shared props as `Flex`. They are documented once, on the
[Flex page](/components/flex):

- [Size](/components/flex#size) — `fill`, `maxWidth`, `aspectRatio`
- [Spacing](/components/flex#spacing) — `gap`, `padding`, `margin`
- [Surface](/components/flex#surface) — `background`, `border`, `radius`, `shadow`
- [Display and behaviour](/components/flex#display-and-behaviour) — `as`, `hide`, `overflow`, `zIndex`
- [Text](/components/flex#text) — `onBackground`, `align`
