`Table` renders an array of your own rows through a list of column definitions.
It keeps the rows as data, so it can sort by the values rather than by the text
on screen, select rows by id, search, and page through them. In 3.0 it is 2.x's
`DataTable` under the short name, and it absorbs 2.x `Table`'s search, row
actions and row clicks.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableExample />}
  codes={[
    {
      code:
`type Invoice = { id: string; customer: string; status: Status; amount: number; issued: string };

const columns: TableColumn<Invoice>[] = [
  { key: "id", header: "Invoice", sortable: true },
  { key: "customer", header: "Customer", sortable: true },
  {
    key: "status",
    header: "Status",
    cell: (invoice) => <Tag size="s" tone={scheme[invoice.status]}>{invoice.status}</Tag>,
  },
  { key: "issued", header: "Issued", sortable: true },
  {
    key: "amount",
    header: "Amount",
    align: "right",
    sortable: true,
    cell: (invoice) => money(invoice.amount),
  },
];

<Table aria-label="Invoices" columns={columns} rows={invoices} />`,
      language: "tsx",
      label: "Table"
    }
  ]}
/>

`Table` is generic over the row type, so `cell` and `sort` receive your rows
typed. A column without `cell` shows `row[key]`. Name the table with `aria-label`,
or point `aria-labelledby` at a heading above it.

## Sorting

A `sortable` column's header is a button. Each press cycles ascending, descending
and back to the rows' own order, and the sorted header carries `aria-sort`. Without
a `sort` function the column compares `row[key]`: numbers as numbers, dates by
time, text in natural order ("Item 2" before "Item 10"), with empty values last
in both directions. Give the column a `sort` comparator, written ascending, when
the key is not a field of the row or its values need their own order:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`const priority = { high: 0, medium: 1, low: 2 };

{ key: "priority", header: "Priority", sortable: true,
  sort: (a, b) => priority[a.priority] - priority[b.priority] }`,
      language: "tsx",
      label: "Comparator"
    }
  ]}
/>

Table keeps the sort itself, starting from `defaultSort`, or follows `sort` and
`onSortChange` when the host owns it. `null` is unsorted. A new sort returns to the
first page.

## Selection and pagination

`selectable` adds a checkbox column. The header checkbox selects or clears the rows
on screen, and shows a mixed state when only some of them are selected; selection
is kept across pages. `getRowId` gives each row the id that selection reports;
without it a row's `id` field is used, or its index. `getRowLabel` names each
row's checkbox for screen readers.

`paginated` shows the rows a page at a time with [`Pagination`](/components/pagination)
below; `perPageOptions` adds a page-size select.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableSelectionExample />}
  codes={[
    {
      code:
`const [selected, setSelected] = useState<string[]>([]);

<Table
  aria-label="Invoices"
  columns={columns}
  rows={invoices}
  getRowId={(invoice) => invoice.id}
  getRowLabel={(invoice) => \`Select \${invoice.id}\`}
  selectable
  selected={selected}
  onSelectionChange={setSelected}
  paginated
  defaultPerPage={5}
  perPageOptions={[5, 10, 25]}
/>`,
      language: "tsx",
      label: "Selection"
    }
  ]}
/>

## Server-side data

When the server sorts and pages, pass the current page's rows with `count`, the
number of rows on the server (or `total`, the number of pages). Table then
neither sorts nor slices the rows: it reports `onPageChange`, `onPerPageChange`
and `onSortChange`, and shows `loading` while you fetch. Give rows a `getRowId`
here, since an index repeats from page to page.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableServerExample />}
  codes={[
    {
      code:
`const [page, setPage] = useState(1);
const [sort, setSort] = useState<TableSort | null>(null);
const { rows, count, loading } = useInvoices({ page, perPage: 5, sort });

<Table
  aria-label="Invoices"
  columns={columns}
  rows={rows}
  count={count}
  perPage={5}
  page={page}
  onPageChange={setPage}
  sort={sort}
  onSortChange={setSort}
  loading={loading}
/>`,
      language: "tsx",
      label: "Server-side"
    }
  ]}
/>

## Rows as arrays

A row can be an array of cells instead of an object: column n then shows the
cell at position n, with no `cell` needed, and sorts by it (an element by its
text). This is how 2.x `Table` took its data, `data={{ headers, rows }}`; in
3.0 each header is a column, its `content` the column's `header`.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Table
      aria-label="Team"
      columns={[{ header: "Name", key: "name", sortable: true }, { header: "Role", key: "role", sortable: true }]}
      rows={[
        ["Alice", "Engineer"],
        ["Bob", "Designer"],
        ["Carol", "Product"],
      ]}
    />
  }
  codes={[
    {
      code:
`<Table
  aria-label="Team"
  columns={[
    { header: "Name", key: "name", sortable: true },
    { header: "Role", key: "role", sortable: true },
  ]}
  rows={[
    ["Alice", "Engineer"],
    ["Bob", "Designer"],
    ["Carol", "Product"],
  ]}
/>`,
      language: "tsx",
      label: "Array rows"
    }
  ]}
/>

## Search

`searchable` adds a field above the table that keeps the rows any of whose cells
reads as holding the query, with a count of what is left. `searchPlaceholder`
sets its placeholder, which also names it.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Table
      aria-label="Team"
      searchable
      searchPlaceholder="Filter by name..."
      columns={[{ header: "Name", key: "name", sortable: true }, { header: "Role", key: "role" }]}
      rows={[
        ["Alice", "Engineer"],
        ["Bob", "Designer"],
        ["Carol", "Product"],
        ["Dan", "Marketing"],
      ]}
    />
  }
  codes={[
    {
      code:
`<Table searchable searchPlaceholder="Filter by name..." columns={columns} rows={rows} />`,
      language: "tsx",
      label: "Search"
    }
  ]}
/>

## Row clicks and actions

`onRowClick` makes the rows clickable and receives the row and its index in
`rows`. `actions` adds a column of icon buttons; each action's `onClick` and
`disabled` receive the row and its index too (2.x passed the index alone).
`rowClassName` and `cellClassName` style a row or a cell from the same
arguments.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Table
  aria-label="Tasks"
  columns={columns}
  rows={tasks}
  onRowClick={(task) => open(task.id)}
  actions={[
    { icon: "edit", label: "Edit", onClick: (task) => edit(task) },
    { icon: "trash", label: "Delete", variant: "primary", tone: "danger", onClick: (task) => remove(task) },
  ]}
/>`,
      language: "tsx",
      label: "Row actions"
    }
  ]}
/>

## Empty and loading

With no rows Table shows an empty state; pass your own as `emptyState`. While
`loading`, skeleton rows stand in for the page (as many as `perPage`), the table is
marked `aria-busy`, and sorting, selection and pagination are disabled.
`loadingState` shows your own placeholder instead of the skeleton rows.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Column fillWidth gap="16">
      <Table
        aria-label="Members"
        columns={[
          { key: "name", header: "Name" },
          { key: "email", header: "Email" },
          { key: "role", header: "Role" },
        ]}
        rows={[]}
      />
      <Table
        aria-label="Members loading"
        loading
        paginated
        defaultPerPage={3}
        columns={[
          { key: "name", header: "Name" },
          { key: "email", header: "Email" },
          { key: "role", header: "Role" },
        ]}
        rows={[]}
      />
    </Column>
  }
  codes={[
    {
      code:
`<Table columns={columns} rows={[]} emptyState={<Text>No members yet.</Text>} />
<Table columns={columns} rows={rows} loading paginated defaultPerPage={3} />`,
      language: "tsx",
      label: "Empty and loading"
    }
  ]}
/>

`stickyHeader` keeps the header row in view while the rows scroll; pair it with
`maxHeight`, which caps the scroll area. `striped`, `hoverable` and `compact` change
the look.
