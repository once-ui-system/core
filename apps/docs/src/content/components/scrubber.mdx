`Scrubber` positions things by **time** rather than by layout. With no tracks it
is a seek bar. Give it tracks and it is an editor timeline: stacked layers of
blocks sharing one playhead, each block selectable, movable and trimmable.
Import it from the media entry point: `import { Scrubber } from "@once-ui-system/core/media";`

It is not [`Timeline`](/components/timeline), which lays out a sequence
of steps or events down the page.

Times are in whatever unit you and the component agree on — milliseconds by
convention, which is what the default `m:ss` formatter assumes. Pass
`formatTime` for anything else, including frames or bars.

## Tracks

Each track is a row of blocks. `movable` lets the body be dragged along the
track, `resizable` puts trim handles on the edges, and `onAdd` turns a click on
empty track space into a new block. Blocks colour themselves from a `tone`,
so layers stay distinguishable.

## Editor grade

The same component carries a full editor timeline. Turn on `ruler` for round
time ticks with a grabbable playhead, give tracks a `label` for a header column,
and the rest is per block or per timeline:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  previewPadding="24"
  preview={<ScrubberEditorExample />}
  codes={[
    {
      code:
`<Scrubber
  duration={24000}
  value={time}
  onValueChange={setTime}
  ruler
  snap
  range={range}
  onRangeChange={setRange}
  markers={[{ id: "c1", time: 2600, label: "Click: Checkout" }]}
  renderPreview={(at) => <img src={frameAt(at)} alt="" width={128} />}
  tracks={[
    {
      id: "take",
      label: "Take",
      resizable: true,
      blocks: [
        { id: "cart", start: 0, end: 5000, label: "Cart" },
        { id: "idle", start: 5000, end: 8000, label: "idle 3 s", variant: "gap",
          description: "Cut: nothing moved on screen for 3 s" },
        { id: "load", start: 14000, end: 17000, label: "Loading", badge: "4×" },
      ],
    },
    {
      id: "audio",
      label: "Audio",
      tone: "info",
      blocks: [{ id: "music", start: 0, end: 24000,
        content: <ScrubberWaveform peaks={peaks} tone="info" /> }],
    },
  ]}
/>`,
      language: "tsx",
      label: "Editor timeline"
    }
  ]}
/>

- **`variant: "gap"`** draws a range that is not in the output: hatched,
  dashed and neutral. Put the reason in `label` and `description`; the
  description is the block's tooltip and what a screen reader announces.
- **`badge`** pins a small pill to the block's corner, such as a speed.
- **`content`** fills the block behind its label. `ScrubberFilmstrip` draws
  thumbnails from frame URLs; `ScrubberWaveform` draws loudness peaks (0 to 1).
- **`highlight`** sweeps a shimmer across the block once. Set it on the blocks
  that just changed under the user, after an AI rewrite or an undo, so the eye
  finds them. Blocks also glide to their new place when their times change.
- **`markers`** put dots on the ruler (clicks, keyframes, chapters).
- **`snap`** makes dragged edges stick to other edges, markers and the
  playhead within 8 px (or the number you pass), with a guide line.
- **`zoom`**, `defaultZoom` and `onZoomChange` magnify the timeline. <Kbd>Ctrl</Kbd>
  or <Kbd>Cmd</Kbd> with the wheel, or a pinch, zooms around the pointer;
  <Kbd>+</Kbd> and <Kbd>-</Kbd> work on the focused timeline. The view follows
  the playhead while it plays.
- **`range`** and `onRangeChange`: <Kbd>Shift</Kbd>-drag on the ruler or an
  empty track selects a span, and a plain click clears it.
- **`renderPreview`** shows what you return above the pointer while it hovers,
  with the time under it. A frame of the video is the usual answer.

## Editing is yours to accept

`onBlockChange` hands back **absolute** times, already clamped to
`[0, duration]` and measured from where the gesture started — not accumulated
per pointer move, so a block cannot drift away from the pointer over a long
drag. Everything past that is your rule: a minimum length, no overlap with the
next block, snapping to a grid. The block renders wherever you put it, so
refusing a change is simply not applying it.

```tsx
onBlockChange={(trackId, blockId, next) => {
  if (next.end - next.start < MIN_MS) return;  // refuse: nothing moves
  setBlocks((current) =>
    current.map((b) => (b.id === blockId ? { ...b, ...next } : b)),
  );
}}
```

`onGestureStart` fires once when a drag begins, which is the moment to snapshot
for undo — one entry per gesture rather than one per pointer move.

## Keyboard and pointer

The track is a `role="slider"`: <Kbd>←</Kbd> and <Kbd>→</Kbd> step the playhead
by `step` (a hundredth of the duration by default), <Kbd>Home</Kbd> and
<Kbd>End</Kbd> jump to either edge. Dragging uses pointer events, so blocks and
playhead work with a mouse, a pen or a finger.

Block gestures stay pointer-driven. Right-clicking a block calls
`onBlockContextMenu` with the event and the ids — build the menu yourself, since
what belongs in it is entirely your application's business.
