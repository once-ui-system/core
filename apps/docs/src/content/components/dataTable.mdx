`DataTable` renders an array of your own rows through a list of column definitions.
Where [`Table`](/components/table) takes cells that are already rendered,
DataTable keeps the rows as data, so it can sort by the values rather than by the
text on screen, select rows by id, and page through them. It draws the same table
as `Table`.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableExample />}
  codes={[
    {
      code:
`type Invoice = { id: string; customer: string; status: Status; amount: number; issued: string };

const columns: DataTableColumn<Invoice>[] = [
  { key: "id", header: "Invoice", sortable: true },
  { key: "customer", header: "Customer", sortable: true },
  {
    key: "status",
    header: "Status",
    cell: (invoice) => <Tag size="s" scheme={scheme[invoice.status]}>{invoice.status}</Tag>,
  },
  { key: "issued", header: "Issued", sortable: true },
  {
    key: "amount",
    header: "Amount",
    align: "right",
    sortable: true,
    cell: (invoice) => money(invoice.amount),
  },
];

<DataTable aria-label="Invoices" columns={columns} rows={invoices} />`,
      language: "tsx",
      label: "DataTable"
    }
  ]}
/>

`DataTable` is generic over the row type, so `cell` and `sort` receive your rows
typed. A column without `cell` shows `row[key]`. Name the table with `aria-label`,
or point `aria-labelledby` at a heading above it.

## Sorting

A `sortable` column's header is a button. Each press cycles ascending, descending
and back to the rows' own order, and the sorted header carries `aria-sort`. Without
a `sort` function the column compares `row[key]`: numbers as numbers, dates by
time, text in natural order ("Item 2" before "Item 10"), with empty values last
in both directions. Give the column a `sort` comparator, written ascending, when
the key is not a field of the row or its values need their own order:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`const priority = { high: 0, medium: 1, low: 2 };

{ key: "priority", header: "Priority", sortable: true,
  sort: (a, b) => priority[a.priority] - priority[b.priority] }`,
      language: "tsx",
      label: "Comparator"
    }
  ]}
/>

DataTable keeps the sort itself, starting from `defaultSort`, or follows `sort` and
`onSortChange` when the host owns it. `null` is unsorted. A new sort returns to the
first page.

## Selection and pagination

`selectable` adds a checkbox column. The header checkbox selects or clears the rows
on screen, and shows a mixed state when only some of them are selected; selection
is kept across pages. `getRowId` gives each row the id that selection reports;
without it a row's `id` field is used, or its index. `getRowLabel` names each
row's checkbox for screen readers.

`paginated` shows the rows a page at a time with [`Pagination`](/components/pagination)
below; `perPageOptions` adds a page-size select.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableSelectionExample />}
  codes={[
    {
      code:
`const [selected, setSelected] = useState<string[]>([]);

<DataTable
  aria-label="Invoices"
  columns={columns}
  rows={invoices}
  getRowId={(invoice) => invoice.id}
  getRowLabel={(invoice) => \`Select \${invoice.id}\`}
  selectable
  selected={selected}
  onSelectionChange={setSelected}
  paginated
  defaultPerPage={5}
  perPageOptions={[5, 10, 25]}
/>`,
      language: "tsx",
      label: "Selection"
    }
  ]}
/>

## Search, filters and columns

`searchable` adds a search field above the table, and a column with a `filter`
adds a select of its `options`. Both are 32px controls, the height of a small
`Button`, so your own controls fit beside them in `toolbar`. DataTable keeps the
search and the filters itself (from `defaultSearch` and `defaultFilters`), or
follows `search` and `filters` with `onSearchChange` and `onFiltersChange`.
`filters` is keyed by column: `{ status: "paid" }`, or a list for a `multiple`
filter. A new search or filter returns to the first page.

The search matches any column's `row[key]`, ignoring case; pass `matchSearch` to
search otherwise. A filter passes rows whose `row[key]` is the picked value (or
holds it, for an array); give it a `match` function for anything else. When
nothing matches, DataTable says so, with a button that clears the search and
filters, instead of the no-data state; pass your own as `noResultsState`.

`hide` drops a column, header and cells, at a breakpoint and below:
`hide: { s: true }`. It is CSS, so the server render is already right. Readers
choose columns themselves from `columnsMenu`; `columnVisibility` with
`onColumnVisibilityChange` puts that choice in your hands, to save it. Give a
column a `label` when its header is not plain text, to name its filter and menu
entry. Narrow this example to see Issued, then Customer, drop out.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableToolbarExample />}
  codes={[
    {
      code:
`const columns: DataTableColumn<Invoice>[] = [
  { key: "id", header: "Invoice", sortable: true },
  { key: "customer", header: "Customer", sortable: true, hide: { xs: true } },
  {
    key: "status",
    header: "Status",
    cell: (invoice) => <Tag size="s" scheme={scheme[invoice.status]}>{invoice.status}</Tag>,
    filter: {
      options: [
        { value: "paid", label: "Paid" },
        { value: "pending", label: "Pending" },
        { value: "overdue", label: "Overdue" },
      ],
    },
  },
  { key: "issued", header: "Issued", sortable: true, hide: { s: true } },
  { key: "amount", header: "Amount", align: "right", sortable: true },
];

<DataTable
  aria-label="Invoices"
  columns={columns}
  rows={invoices}
  searchable
  columnsMenu
  toolbar={<Button size="s" variant="secondary" prefixIcon="download">Export</Button>}
  paginated
  defaultPerPage={5}
/>`,
      language: "tsx",
      label: "Toolbar"
    }
  ]}
/>

`Table` takes the same `hide` on its headers.

## Server-side data

When the server sorts and pages, pass the current page's rows with `count`, the
number of rows on the server (or `total`, the number of pages). DataTable then
neither sorts nor slices the rows: it reports `onPageChange`, `onPerPageChange`
and `onSortChange`, and shows `loading` while you fetch. Give rows a `getRowId`
here, since an index repeats from page to page.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableServerExample />}
  codes={[
    {
      code:
`const [page, setPage] = useState(1);
const [sort, setSort] = useState<DataTableSort | null>(null);
const { rows, count, loading } = useInvoices({ page, perPage: 5, sort });

<DataTable
  aria-label="Invoices"
  columns={columns}
  rows={rows}
  count={count}
  perPage={5}
  page={page}
  onPageChange={setPage}
  sort={sort}
  onSortChange={setSort}
  loading={loading}
/>`,
      language: "tsx",
      label: "Server-side"
    }
  ]}
/>

With `count` or `total` the search and filters are the server's to apply: DataTable
reports them and shows the rows you pass. Rather than one handler per piece,
`onQueryChange` hands you the page, page size, sort, search and filters together,
once per change, ready to fetch with. `keepRowsWhileLoading` keeps the last page on
screen, dimmed, while the next one loads, so the table does not flash skeletons on
every keystroke. Debounce the fetch if your API is slow to answer.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={<DataTableServerQueryExample />}
  codes={[
    {
      code:
`const [query, setQuery] = useState<DataTableQuery>({
  page: 1, perPage: 5, sort: null, search: "", filters: {},
});
const { rows, count, loading } = useInvoices(query);

<DataTable
  aria-label="Invoices"
  columns={columns}
  rows={rows}
  count={count}
  page={query.page}
  perPage={query.perPage}
  sort={query.sort}
  search={query.search}
  filters={query.filters}
  onQueryChange={setQuery}
  searchable
  loading={loading}
  keepRowsWhileLoading
/>`,
      language: "tsx",
      label: "Server query"
    }
  ]}
/>

## Empty and loading

With no rows DataTable shows an empty state; pass your own as `emptyState`. While
`loading`, skeleton rows stand in for the page (as many as `perPage`), the table is
marked `aria-busy`, and sorting, selection and pagination are disabled.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Column fillWidth gap="16">
      <DataTable
        aria-label="Members"
        columns={[
          { key: "name", header: "Name" },
          { key: "email", header: "Email" },
          { key: "role", header: "Role" },
        ]}
        rows={[]}
      />
      <DataTable
        aria-label="Members loading"
        loading
        paginated
        defaultPerPage={3}
        columns={[
          { key: "name", header: "Name" },
          { key: "email", header: "Email" },
          { key: "role", header: "Role" },
        ]}
        rows={[]}
      />
    </Column>
  }
  codes={[
    {
      code:
`<DataTable columns={columns} rows={[]} emptyState={<Text>No members yet.</Text>} />
<DataTable columns={columns} rows={rows} loading paginated defaultPerPage={3} />`,
      language: "tsx",
      label: "Empty and loading"
    }
  ]}
/>

`stickyHeader` keeps the header row in view while the rows scroll; pair it with
`maxHeight`, which on DataTable caps the scroll area. `striped`, `hoverable` and
`compact` work as on `Table`.
