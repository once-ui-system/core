`Flex` is the element the rest of Once UI is made of. It renders a flex
container and takes every layout, spacing, size and surface prop in the system,
so a page is composed by nesting it rather than by writing CSS.

You will rarely write `Flex` itself. `Row` and `Column` are the same component
with `direction` preset, and reading `<Column gap="16">` beats reading
`<Flex direction="column" gap="16">`:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Column gap="16">   // Flex, direction: column
<Row gap="16">      // Flex, direction: row
<Flex s={{ direction: "column" }}>  // Flex, when the direction changes`,
      language: "tsx",
      label: "Prefer Row and Column"
    }
  ]}
/>

Reach for `Flex` directly when the direction is conditional — a row on desktop
that stacks on a phone — since that is the one thing a preset cannot express.

## Element

`as` picks the element, and the types follow it: `as="a"` takes `href`,
`as="form"` types `onSubmit` for a form, and a ref is typed by the element.
A list loses its bullets and indent and a button its browser chrome, at zero
specificity, so any spacing, background or border prop still applies; a
button is `type="button"` unless you set `type`. For a list that keeps its
markers, use `List`.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Column as="ul" gap="8">              // no bullets, no indent
    <Row as="li">...</Row>
</Column>
<Row as="a" href="/pricing" gap="8">...</Row>
<Row as="button" padding="12" radius="m" onClick={open}>...</Row>
<Column as="form" onSubmit={(event) => save(event.currentTarget)}>...</Column>`,
      language: "tsx",
      label: "as"
    }
  ]}
/>

Only `Flex`, `Row`, `Column`, `Grid`, `Text`, `Heading` and `VisuallyHidden`
take `as`. A component built on them (Card, Tag, Avatar…) renders its own
element; wrap it to place it in a list: `<Column as="li"><Card /></Column>`.

## Direction and alignment

`horizontal` and `vertical` are named for the axis you see, not for flexbox's
main and cross axis, so they mean the same thing whichever way the container
runs.

## Size

Sizes take a spacing token, a number, or a CSS length such as `"40rem"` or `"50%"`. A number is on the token scale: `width={40}` renders as `width="40"` does, 2.5rem, and both follow `data-scaling`, so at the default root size and scaling a number is that many pixels. Write `"40px"` for a length that must not scale. `fill` and
`fit` are the two you want most: fill the parent, or shrink to the content.

## Spacing

Space between siblings is `gap` on the parent; space inside an element is
`padding`. Prefer both over `margin` — a layout built from gaps stays correct
when a child is added, removed or reordered.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Column gap="16" padding="24">    // space between children, space inside
<Column marginBottom="16">        // last resort: space against a sibling
<Row marginLeft="auto">           // push to the end of a row
<Column maxWidth="40rem" marginX="auto">  // centre a block`,

## Surface

Background, border, radius and shadow are all tokens. A colour is a scheme and a
weight (`brand-medium`, `neutral-alpha-weak`), never a hex.

### Effects without a style object

`blendMode`, `blur`, `backdropBlur` and `userSelect` are classes, so setting
them keeps `Flex` and `Grid` server components — a `style` object does not.
The blur scale is the static spacing steps: `xs` 0.25rem, `s` 0.5rem, `m`
1rem, `l` 2rem, `xl` 3rem; a number is on the same token scale (`8` is 0.5rem), written inline on the server.
`blur` sets the whole `filter`, so a blur combined with another filter
function still goes in `style`.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Flex position="absolute" fill blur="xl" blendMode="color-dodge" pointerEvents="none" />
<Column background="overlay" backdropBlur="m" padding="24">...</Column>
<Row userSelect="none"><Text>00:42</Text></Row>`,
      language: "tsx",
      label: "Effects"
    }
  ]}
/>

`transform` is deliberately not a prop. It is what animations drive, frame by
frame, so it stays in `style`; for a static shift, `translateX` and
`translateY` do the same without leaving the server.

### A themed subtree

`theme`, `themeBorder`, `themeSolid` and `themeSurface` restyle everything
inside, the way `ThemeProvider` restyles the page: they write `data-theme`,
`data-border`, `data-solid` and `data-surface`, typed with the provider's own
values. `theme="dark"` renders the subtree dark; `showIn="dark"` only shows
or hides an element depending on the theme around it.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Column theme="dark" background="page" padding="40">...</Column>
<Row themeBorder="rounded" gap="8">...</Row>
<Row themeSolid="contrast">...</Row>`,
      language: "tsx",
      label: "Themed subtree"
    }
  ]}
/>

## Cursor

`cursor` takes a CSS keyword (`"interactive"` for anything clickable), a
preset, or a node to draw at the pointer.

### Presets

A preset restyles every cursor inside the element: the arrow over the page,
the pointer over buttons and links, the I-beam over text fields and the
blocked sign over disabled controls. The browser draws it, so it never lags
and touch screens never see it. `soft` is a dark wedge with a white rim that
reads on light and dark pages alike, `rounded` is the classic arrow rounded
off and turns light in dark mode, and `dot` is a small dot that opens into a
ring over anything clickable. `"system"` turns a preset off below it.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Row fillWidth gap="12" s={{ direction: "column" }}>
      {["soft", "rounded", "dot"].map((preset) => (
        <Column key={preset} cursor={preset} flex={1} gap="12" padding="16" radius="l" border="neutral-alpha-medium" background="surface">
          <Text textVariant="label-strong-s">{preset}</Text>
          <Input id={`cursor-${preset}`} placeholder="Type here" />
          <Row gap="8">
            <Button size="s">Click</Button>
            <Button size="s" variant="secondary" disabled>Disabled</Button>
          </Row>
        </Column>
      ))}
    </Row>
  }
  codes={[
    {
      code:
`<Column cursor="soft">
  <Input id="name" placeholder="Type here" />   // I-beam
  <Button>Click</Button>                         // pointer
  <Button disabled>Disabled</Button>             // blocked
</Column>`,
      language: "tsx",
      label: "Preset"
    }
  ]}
/>

For the whole app, set `cursor` in the `style` section of `once-ui.config`
(or on `ThemeProvider`). `ThemeInit` writes it before the first paint:

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`// once-ui.config
const style = {
  theme: "system",
  cursor: "soft", // "rounded", "dot" or "system"
  // ...
};`,
      language: "ts",
      label: "App-wide"
    }
  ]}
/>

Controls follow the preset on their own. `cursorInteractive: "default"`
still keeps the arrow over them, the preset's arrow.

### A node that follows the pointer

Pass a node and it is drawn at the pointer over the element's own surface. It
steps aside wherever the native cursor is back, over a button, a link, a text
field or a nested element with a cursor of its own, so the two never show at
once. It moves without a React render, fades in and out (instantly with
reduced motion), and touch input never shows it.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Column
      fillWidth
      gap="16"
      padding="32"
      radius="l"
      border="neutral-alpha-medium"
      background="surface"
      cursor={<Row as="span" inline fit solid="brand-strong" padding="12" radius="full"><Icon name="arrowUpRight" onSolid="brand-strong" /></Row>}
    >
      <Text onBackground="neutral-weak">Hover the card, then the button.</Text>
      <Row>
        <Button size="s">The pointer comes back here</Button>
      </Row>
    </Column>
  }
  codes={[
    {
      code:
`<Column
  cursor={<Row as="span" inline fit solid="brand-strong" padding="12" radius="full"><Icon name="arrowUpRight" /></Row>}
>
  <Text>Hover the card, then the button.</Text>
  <Button>The pointer comes back here</Button>
</Column>`,
      language: "tsx",
      label: "Follower"
    }
  ]}
/>

## Responsive

Every prop above can be overridden per breakpoint. Pass an object to `xl`, `l`,
`m`, `s` or `xs` — they cascade down, so `s` also applies at `xs` unless `xs`
says otherwise. This is how layout adapts; media queries are never needed.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Row gap="24" s={{ direction: "column", gap: "16" }}>
    <Column fillWidth m={{ hide: true }}>Sidebar</Column>
    <Column fill>Content</Column>
</Row>`,
      language: "tsx",
      label: "Breakpoints"
    }
  ]}
/>
