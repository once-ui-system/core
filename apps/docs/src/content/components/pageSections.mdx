A landing page is a stack of sections: a hero, what the product does, what
people say about it, the prices, the questions, a last call and a way to get in
touch. `@once-ui-system/blocks` has one tag for each. You fill in its content
through props and pick its arrangement with `layout`. Every layout shows the
same fields, so switching layouts never hides anything you wrote.

Each section reads its props defensively. Content often comes from an editor,
a JSON file or a model, so a missing, misspelled or mistyped prop renders as
nothing instead of throwing. A section never shows sample copy of its own.

The sections add no outer padding. The page sets the gutter and the space
between sections.

The page's opening: eyebrow, headline, lead, two buttons and a picture. The
headline is the page's `h1`. Each button shows only when it has both a label
and a link.

Layouts (`heroLayouts`):

- `split` (default): the words beside a portrait picture.
- `centered`: centered words over a wide picture.
- `cover`: the picture in a tall rounded frame, the words over its faded foot.
- `boxed`: the words and a picture inside a framed box.
- `fullscreen`: the picture fills most of the screen, the headline large at its foot.
- `halves`: the section cut in two, the words on one half and the picture filling the other.
- `editorial`: a very large headline, the lead and buttons side by side under a rule, the picture a wide band beneath.

`heroLayoutGuide` holds one sentence per layout on when it suits, for an
editor's tooltip or a model choosing one.

## Sections

`Sections` renders a page from stored data: a list of `{ id, type, props }`
items, as a page builder or a CMS saves them. `type` is one of `hero`,
`features`, `about`, `stats`, `gallery`, `testimonials`, `team`, `pricing`,
`faq`, `logos`, `cta` and `contact`. A type the package does not have goes to
`renderCustom`, or is left out, so a page saved by a newer editor still
renders. `resolveHref` is passed to every section.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  previewPadding="24"
  preview={

      <Sections
        items={[
          { id: "hero", type: "hero", props: { layout: "centered", title: "Ember", description: "Coffee, bread and a quiet table." } },
          { id: "stats", type: "stats", props: { layout: "strip", items: [{ value: "8:00", label: "Opens" }, { value: "40", label: "Seats" }, { value: "6", label: "Kinds of bread" }] } },
          { id: "cta", type: "cta", props: { layout: "minimal", title: "Drop by", primaryLabel: "Find us", primaryHref: "#" } },
        ]}
      />
    </Column>
  }
  codes={[
    {
      code:
`import { Sections } from "@once-ui-system/blocks";

<Sections
  items={page.sections}
  resolveHref={(href) => \`/de\${href}\`}
  renderCustom={(item) => item.type === "menu" && <Menu {...item.props} />}
/>

// page.sections
[
  { id: "hero", type: "hero", props: { layout: "centered", title: "Ember", description: "Coffee, bread and a quiet table." } },
  { id: "stats", type: "stats", props: { layout: "strip", items: [{ value: "8:00", label: "Opens" }, { value: "40", label: "Seats" }] } },

      language: "tsx",

`Sections` adds no space between sections. Wrap it in a `Column` with a `gap`
to set the rhythm. `sectionComponents` maps each type to its component if you
render the list yourself.

## Schema

`sectionSchemas` describes every section as plain data: its `component` name,
a `label`, a one-line `description`, its `layouts` (the first is the default),
its `fields` and a filled-in `sample`. It has no functions, so
`JSON.stringify(sectionSchemas)` gives an editor panel or an agent the full
contract. `sectionTypes` lists the types in the order an editor offers them,
and `isSectionType(value)` checks a stored type.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`import { sectionSchemas, sectionTypes } from "@once-ui-system/blocks";

sectionSchemas.pricing.layouts; // ["cards", "list"]
sectionSchemas.pricing.fields.map((field) => field.key);
// ["layout", "eyebrow", "title", "description", "items", "width"]

// A new section starts from its sample.
const section = { id: crypto.randomUUID(), type: "faq", props: sectionSchemas.faq.sample };`,
      language: "tsx",
      label: "Schema"
    }
  ]}
/>

## API reference

Every section takes these props. Lists of items are documented with each
section above.

| Prop | Type | Default | Sections |
| --- | --- | --- | --- |
| `layout` | `string`: one of the section's layouts | the first layout | all |
| `width` | `"s"`, `"m"` or `"l"`: how wide the content runs | `"l"` | all |
| `eyebrow` | `string` | | all |
| `title` | `string` | | all |
| `description` | `string` | | all |
| `resolveHref` | `(href: string) => string`: rewrites every link the section renders | | all |
| `primaryLabel`, `primaryHref` | `string` | | Hero, About, Cta, Contact |
| `secondaryLabel`, `secondaryHref` | `string` | | Hero, About, Cta |
| `image`, `imageAlt` | `string` | | Hero, About, Cta (`cover`) |
| `columns` | `"2"`, `"3"` or `"4"` | `"3"` | Features, Team |
| `items` | an array of row objects, per section | `[]` | Features, Testimonials, Pricing, Faq, Gallery, Logos, Stats, Team |

`Sections` takes `items` (`{ id?, type, props? }[]`), `resolveHref` and
`renderCustom` (`(item, index) => ReactNode`).
