The `Scroller` component creates a scrollable container with automatic navigation buttons that appear when content overflows. It's perfect for horizontal or vertical scrolling of content like cards, images, or any elements that might not fit in the available space.

## Track mode

Set any of `infinite`, `markers`, `draggable`, `step`, `clip`, `proximity`, `active`, `onActiveChange`, `controlPlacement` or `tile` and the children become a run of tiles moved by a transform: controls, drag, optional wrap-around, markers and proximity scaling. `tile` styles the box each item sits in (its size, aspect ratio); the other props style the Scroller. It was `ScrollContainer` in 2.x, which took the items as `items` and the tile props as its own.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Scroller tile={{ aspectRatio: "16/9" }}>{Array(8).fill(0).map((_, i) => (
        <Column key={i} fill padding="8">
          <Background
            fill
            background="neutral-alpha-weak"
            border="neutral-alpha-medium"
            radius="l"
            lines={{ display: true, color: "neutral-alpha-weak" }}
          />
        </Column>
      ))}</Scroller>
  }
  codes={[
    {
      code:
`<Scroller draggable><YourContent /><YourContent /><YourContent /></Scroller>`,
      language: "tsx",
      label: "ScrollContainer"
    }
  ]}
/>

### Infinite

Past the last item the track continues into the first, in the same direction, with no rewind. Both controls stay enabled.

  infinite>{items}</Scroller>`,

/>

### Markers

Markers show how many items there are and which one is in front, and jump to one when pressed. `markers` takes `true` to put them opposite the controls, or `"top"` / `"bottom"` to name the side.

  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Scroller
  markers="bottom"
  controlPlacement="top-end">{items}</Scroller>`,
      language: "tsx",
      label: "Markers"
    }
  ]}
/>

### Drag

The track follows a pointer — mouse, pen or finger. A gesture is claimed for one axis on its first movement and never reassigned, so a vertical swipe still scrolls the page. Let go past a fifth of a tile, or flick, and the track advances; anything shorter settles back. Without `infinite` the track resists being pulled past either end and springs back.

A drag that ends on a tile does not also open it — the click is swallowed before it reaches the item.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Scroller
  draggable={false}>{items}</Scroller>`,
      language: "tsx",
      label: "Disable drag"
    }
  ]}
/>

### Proximity

`proximity` scales each tile by how far it is from the one in front, so the run has a focus that moves with it. It is continuous rather than stepped: halfway through a drag the outgoing and incoming tiles are the same size, so the emphasis crosses between them as the pointer moves instead of snapping when the track settles.

Pass `true` for a gentle default, or a number for how much smaller each whole step away is, as a fraction — `0.08` makes the immediate neighbour 92%. Tiles stop shrinking at 72%, so a long run does not trail off into nothing.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Scroller
      proximity
      infinite tile={{ aspectRatio: "16/9" }}>{Array(8).fill(0).map((_, i) => (
        <Column key={i} fill padding="8">

            fill
            background="neutral-alpha-weak"
            border="neutral-alpha-medium"
            radius="l"
            lines={{ display: true, color: "neutral-alpha-weak" }}

        </Column>

  }
  codes={[

### Driving it from your own UI

`active` brings an item to the front by its index, and `onActiveChange` reports the item that arrived there, however it got there — a control, a marker or a drag. Together they let something outside the component stand in for the markers: a row of names, a set of thumbnails, a table of contents.

`active` is a command, not a lock. The run still moves on its own, and it is `onActiveChange` that keeps the caller's own state level with it. An `active` that never changes does not pin the run in place.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`const [active, setActive] = useState(0);

<Row gap="8">
  {names.map((name, i) => (
    <Button
      key={name}
      variant={i === active ? "primary" : "tertiary"}
      onClick={() => setActive(i)}
    >
      {name}
    </Button>
  ))}
</Row>

<Scroller
  active={active}
  onActiveChange={setActive}
  infinite>{items}</Scroller>`,
      language: "tsx",
      label: "Driving it from your own UI"
    }
  ]}
/>

### Custom Styling

Every prop other than the ones listed below is applied to each tile, so a tile is styled from out here.

Tiles carry no appearance of their own: no border, no radius, no aspect ratio. The only sizing they arrive with is a `minWidth` floor, so a carousel of anything that fills its parent has something to fill. Give them whatever shape the content needs.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  codes={[
    {
      code:
`<Scroller tile={{ border: "brand-alpha-medium", background: "brand-alpha-weak", onClick: (e) => {
    console.log('Item clicked');
  }, cursor: "interactive" }}>{items}</Scroller>`,
      language: "tsx",
      label: "Custom Styling"
    }
  ]}
/>


## Auto

`auto` loops the children across on their own, a marquee with no controls. `auto={{ speed, hover, reverse, gap }}` sets the speed (a multiplier, or `"slow"`/`"medium"`/`"fast"`), what hovering does (`"slow"`, `"pause"` or `"none"`), the direction and the space after each copy. It was `AutoScroll` in 2.x.

## Accessibility

The Scroller component includes the following accessibility features:

- Scroll buttons are named "Scroll Previous" and "Scroll Next"; `labels` translates them
- Keyboard navigation support for the scroll buttons
- Preserves keyboard navigation and click events of child elements
