`Tooltip` is a non-interactive floating container used to communicate short hints or descriptions. It can be rendered manually or combined with a hover/focus trigger component. It is automatically hidden below the `m` breakpoint.

## Info icon

A Tooltip with `content` and no children renders a focusable info icon as its trigger: the "what is this?" affordance that reveals a sentence on hover or focus, announced as the icon's description. `size` sizes the icon and `aria-label` names it ("More information" by default). With children, `content` opens from them instead. It was `InfoTip` in 2.x.

<CodeBlock
  marginTop="16"
  marginBottom="24"

      <Text textVariant="label-default-s">Bitrate</Text>
      <Tooltip content="Higher bitrates keep more detail in fast motion, at a larger file size." />

### Sizing

`size` takes the same tokens as [`Icon`](/components/icon). Match it to
the text it sits beside — `xs` next to a label, `s` next to body copy — so the
icon reads as part of the line rather than an object dropped into it.

<CodeBlock
  marginTop="16"
  marginBottom="24"
  preview={
    <Row gap="16" vertical="center" paddingY="24" horizontal="center" fillWidth>
      <Tooltip size="xs" content="Extra small" />
      <Tooltip size="s" content="Small" />

### When not to use it

Hover-only content is invisible on touch and to anyone scanning rather than
pointing, so an `Tooltip` must never carry information the reader needs in order
to make the choice in front of them. That belongs in a visible description —
[`Setting`](/components/setting) has a `description` prop for exactly
this. Reserve `Tooltip` for the second sentence: the caveat, the unit, the
reason a default is what it is.

Anything longer than a sentence or two wants a link to a page, not a tip.

### In a Setting

[`Setting`](/components/setting) renders an `Tooltip` for you when you
pass its `info` prop, which is the usual way you will meet this component.
