One pattern for every landing page on a phone. Put `HeaderMenu` where the menu button goes, usually at the right end of the header. The header never moves: the button's lines fold into a cross in the same spot, and the menu grows down out of the header as a panel that fills the rest of the screen, its rows arriving one after another. Closing folds it back up. `footer` pins the page's main call to action to the panel's foot.

Following a link, Escape, or the button again closes it, and so does a window wide enough for the header's own links (`below`, default `"m"`). The panel keeps the look of the StyleScope the header sits in.

## Behaviour

- **In place:** the menu button is the cross. A second button in the corner, or a header redrawn inside a drawer, makes the close control jump; this does not.
- **Under the header:** the panel starts at the bottom of the nearest `header` element and covers the page below it, with page scroll locked.
- **Keyboard:** opening moves focus to the first link, Tab off either end returns to the button, Escape closes and returns focus.
- **Controlled or not:** `open` / `defaultOpen` / `onOpenChange`.

For a dashboard on a phone, use `Sidebar`: below `mobileBelow` it becomes a left drawer on its own.
